# Iloha Trajectory Studio

リポジトリのルートで起動します。実機には接続しません。元のデータセットは読み取り専用で扱い、書き出し操作時に新しいデータセットを作成します。

```sh
uv run iloha_trajectory_web.py
```

ブラウザで <http://127.0.0.1:8765> を開いてください。NumPy、PyTorch、Unity、Node、CDNは起動時に不要です。Python 3.12以降とPyArrowを使用し、`uv run` がスクリプト専用の依存環境を用意します。PyArrowが導入済みなら `python iloha_trajectory_web.py` でも起動できます。

```sh
uv run iloha_trajectory_web.py --datasets-root /path/to/datasets --port 8765
```

## 操作

- 初期状態で `iloha-best` → `iloha-common` のエピソード0を読み込みます。別のデータセットやエピソードも追加できます。クリップの↑で順番を変更できます。
- 開始・終了時刻または2つのトリムハンドルで不要な区間を除きます。時刻は**元データの秒数**です。
- 各クリップに `iloha_catch_replay.py` と同じ5つの速度設定があります。ベース速度、追加倍率上限、グリッパー前後の余白、追加倍率までの範囲、グリッパー判定閾値を独立に指定します。初期値はCLI実装の `1 / 2 / 0.5 / 1 / 0.0001` に合わせています。
- クロスディゾルブは速度変更後の末尾・先頭を重ね、smoothstepの重みで関節角を混合します。線形補間は両端の間に移動区間を追加します。「滑らかな補間」は両端の速度を使う三次Hermite補間で、速度を接続しますが位置のオーバーシュートは許容します。「そのまま接続」は境界を補間しません。
- 接続時間は**速度変更後の秒数**です。処理順は「各元クリップの速度スケジュールを計算 → 指定区間を取り出して時間を変更 → 境界接続 → 追従シミュレーション」です。グリッパーからの距離はトリム前の元エピソードで判定します。
- 灰色は編集後の理想手先軌道を全区間表示します。青い軌跡は初期状態では非表示です。3Dビューの「青い軌跡」をオンにすると推定実軌道を開始から現在まで表示し、オフで非表示にできます。切替は現在のロボット姿勢や灰色の理想軌道には影響しません。両腕の現在姿勢もそれぞれ点と線で描きます。手首ロールとグリッパー開度は先端の横線に反映します。
- 再生バーで任意の時刻に移動できます。巻き戻すと青い軌跡も戻ります。「境界へ」で接続区間の手前に移動できます。
- ドラッグで3D回転、Shift+ドラッグで平行移動、ホイールで拡大縮小できます。正面・上面・側面の視点もあります。
- プレビュー速度は画面の再生速度だけを変更します。物理的な再生速度の変更は各クリップの速度設定で行います。
- 「設定を保存／読込」でクリップ選択・編集・速度・制限設定を保存できます。「軌道を書き出す」で理想軌道を新しいLeRobotデータセットに保存できます。実機再生スクリプトへの自動投入は行いません。

## 理想軌道のデータセット書き出し

右上の「軌道を書き出す」で保存名とFPS（初期値30）を指定します。保存名の初期値は `iloha-best-common` です。

トリミング・境界接続は反映します。**各クリップの速度変更、速度・加速度・電流制限、慣性モデル、終了保持は適用しません。** 高速化済みのプレビュー配列を流用せず、元のフレーム列から再構成します。接続時間は同じ入力値を「元データの秒数」として使うため、速度を変更したプレビューとは接続部分の形状が異なる場合があります。

```text
datasets/iloha-best-common/
  data/chunk-000/file-000.parquet
  meta/info.json
  meta/stats.json
  meta/tasks.parquet
  meta/episodes/chunk-000/file-000.parquet
  trajectory_settings.json
```

データは単一エピソードとしてALOHA座標に戻して保存し、`iloha_catch_replay.py` と同じ列名・形状にします。`observation.state` には理想指令を複製し、実測値ではないことを設定JSONに記録します。速度・制限設定は `trajectory_settings.json` に分離し、元クリップの区間、速度設定、接続方式、モデル設定、出力後の区間情報も残します。既存の保存名はエラーにし、上書きしません。

同じ画面から設定JSONと、速度未適用の理想軌道JSONを単独でダウンロードすることもできます。

## 近似モデル（v3）

`ref_ik.cs` のリンク長 `[0.1, 0.305834, 0.2033, 0.0967, 0.07015, 0.03]` mと角度変換を逆算した順運動学を使用します。解析座標はZ上、+YがUnityの+X（右）です。左ベースY=-0.295 m、右Y=+0.295 m、間隔590 mm。データの左右チャンネルや関節角度の符号は入れ替えません。

### 変更した計算

実機は少なくとも等速再生に追従するというユーザー確認を前提とし、**静止姿勢を維持できている閉ループ系の、運動に伴う追従差**を近似します。旧版の未検証の棒重力による自由落下・PDモデルは廃止しました。メーカーのゲインを再現したり、実機へ外部P制御を追加したりはしません。

片腕6 kgをリンク長に比例配分する一様棒は、姿勢ごとの関節慣性Jの計算に使用します。下流リンクの軸からの距離の二乗を棒上で積分し、半径2 cmの断面慣性も加えます。重力関数は数値検証用に残っていますが、v3の運動計算には使いません。

```text
加速トルク余裕 = max(0, min(Kτ × 電流上限, 型番別ピークトルク) − Kτ × 静止分予約電流)
電流による加速度上限 = 加速トルク余裕 / J
実効加速度上限 = min(電流による上限, 追加指定の加速度上限)
目標速度 = 隣接する軌道サンプルの角度差 / 時間差
追従速度 = clip(目標速度 + 位置誤差の回復分, ±速度上限)
加速度 = clip((追従速度 − 現在速度) / dt, ±実効加速度上限)
角度 += (旧速度 + 新速度) × dt / 2
```

位置誤差の回復分は、相対的な停止距離と加速度上限から計算します。フレームごとに停止点を作る旧方式と異なり、**移動中の目標速度を引き継いで追従**します。先頭は記録開始姿勢・速度ゼロ、フレーム境界やクリップ境界で位置・速度をリセットせず240 Hzで積分、表示サンプルは60 Hzです。速度・加速度・余裕電流の制限は実際の計算に作用し、出力角を理想角へ強制コピーする処理はありません。

### 加速度設定の意味

- **初期値0は「追加指定なし」**です。無限加速度ではなく、メーカー出力・設定電流・棒の慣性から求める加速度制限が働きます。
- 正の加速度を入力すると、そのrad/s²を厳密な追加上限として適用します。
- 「コードのRobStride PP上限を適用」でJ1〜J3に速度π rad/s・加速度π/2 rad/s²を設定できます。これは `aloha_arm_controller.py` の設定値です。
- 旧モデルはこのπ/2を実機の有効な応答上限と同一視し、DYNAMIXELにも一律適用していました。DYNAMIXELにこの設定を行うコードはありません。またRobStrideの記述されたPPパラメーターと、逐次目標更新中の実機応答の対応は未検証です。**v3初期値は旧版と同じ加速度設定ではありません。** π/2を厳密な上限とみなす場合に等速追従と矛盾する点が、メーカー仕様だけで解明できたという主張ではありません。
- 「モデル初期値」で追加上限0に戻します。「上限を2倍」は指定済みの正の加速度上限を2倍にし、0は0のままです。
- 「各クリップを1倍速にする」はbase_speedとmax_speedupを両方1にします。プレビュー速度だけの変更とは異なり、物理計算に渡す軌道時間を戻します。

### 電流予算と妥当性の範囲

静止分の予約電流は各関節ごとに任意入力できます。保持などで使う分を加速用の予算から差し引く設定で、初期値0は**未予約**であって、実機の保持電流がゼロと分かったわけではありません。未予約時の加速余裕は楽観的です。計算結果の `currents` は加速分の電流であり、実機の総電流ではありません。

実機での総トルク・保持電流・電流換算・速度に伴う出力低下が未同定のため、これは**静止保持が成立している範囲での、速度変更や制限変更の比較モデル**です。電源断や静止保持の破綻を予測するものではありません。軸間の慣性結合・コリオリ項・摩擦・バックラッシュ・通信遅延・電源降下・熱保護・過負荷時間・グリッパー動力学は未再現です。

`iloha_catch_server.py` の記録処理は `robot.old_action` から `action` と `observation.state` の両方を作っています。commonでは両列が全フレームで一致し、bestにも多数の一致があります。これを実測フィードバックとして使うと検証が循環するため、**これらの列による実測同定は行っていません**。下記の偏差はモデルと理想指令の比較で、実機との誤差を測った数値ではありません。

### 関節別のメーカー仕様

ユーザー確認の構成は左右ともJ1=03、J2=06、J3=00です。

| 関節 | 型番・出典 | 定格 / ピーク Nm | 公開Kτまたは概算比 |
| --- | --- | --- | --- |
| J1 | [RobStride 03](https://www.robstride.com/products/robStride03) | 20 / 60 | 2.36 Nm/Arms |
| J2 | [RobStride 06](https://www.robstride.com/products/robStride06) | 11 / 36 | 1.10 Nm/Arms |
| J3 | [RobStride 00](https://robstride.com/products/robStride00) | 5 / 14 | 1.48 Nm/Arms |
| J4・J5 | [XM540-W270](https://emanual.robotis.com/docs/en/dxl/x/xm540-w270/) | 未規定 / 10.6（ストール、12 V） | 10.6 / 4.4 ≈ 2.409 Nm/A |
| J6 | [XM430-W350](https://emanual.robotis.com/docs/en/dxl/x/xm430-w350/) | 未規定 / 4.1（ストール、12 V） | 4.1 / 2.3 ≈ 1.783 Nm/A |

Kτは出力軸換算済みで減速比を再度掛けません。RobStrideの公開値は相電流実効値当たり。初期設定はCAN Iqを相電流ピークと仮定して√2で割り、1.6688 / 0.7778 / 1.0465 Nm/Aを使用します。この電流の解釈は切替・手動編集が可能です。DYNAMIXELはストール値の比による概算で、正確なトルク定数や連続定格ではありません。

電流初期値は左右J2=16 A、J6=2.3 A、その他4 A。速度初期値はRobStrideがπ rad/s、DYNAMIXELは各型番の12 V無負荷速度です。全関節で無負荷速度を超える指令速度は制限します。ただし最大トルクと無負荷速度を同時に出せることを保証しません。DYNAMIXELの実機コードの通常位置モードに電流制御を追加するものでもありません。

旧プロジェクトの速度・加速度・電流・Kτは読み込み時に保持します。廃止したPD応答・減衰・重力補償フラグは削除し、モデル版を3に更新します。初期値に切り替えたい場合は「モデル初期値」を使用してください。モデル式・型番・出典・予約電流などの前提は設定JSONに保存し、理想データセットの値には反映しません。

### 実データでの回帰比較

best→common、クロスディゾルブ1秒、6 kg、v3初期制限（追加加速度上限なし・静止分未予約）、終了保持2秒で比較しました。各クリップのmax_speedup=1、base_speedだけ変更しています。

| 再生速度 | 手先RMS偏差 | 最大偏差 |
| --- | --- | --- |
| 1倍 | 約1.0 mm | 約37.7 mm |
| 2倍 | 約6.1 mm | 約86.5 mm |
| 4倍 | 約47.7 mm | 約247.1 mm |

等速でも開始・急な変化点では過渡偏差があり、完全一致ではありません。ブラウザ回帰テストには等速のRMS 3 mm未満・最大50 mm未満と、2倍・4倍で制限による偏差が増えることを入れています。これは**入力データに対するモデルの回帰条件**であり、独立した実機計測による精度保証ではありません。

## 検証

```sh
node --test tests/test_iloha_trajectory_core.mjs
uv run --no-project --with pyarrow python -m unittest discover -s tests -p test_iloha_trajectory_web.py
# 実データを一時領域にコピーし、検証用サーバーとインストール済みChromeを使用
uv run --no-project --with pyarrow --with playwright python tests/check_iloha_trajectory_browser.py
```

`meta/info.json` だけでは再生できません。`data/**/*.parquet` の `action`, `episode_index`, `frame_index` 列を読み込みます。データ欠損時に自動で人工データへ置換することはありません。動作確認用デモは明示的なボタン操作でのみ読み込みます。
