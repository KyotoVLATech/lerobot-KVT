今回の初回エピソードは replay の warmup 前だったため、未学習の編集を使わず X-VLA の候補行動を収集しました。
次回の再開では、保存済み Q・編集ポリシー・replay を利用できます。
実行周波数はエピソード全体で約 21.9 Hz です。指定の 30 Hz は各制御ステップの目標で、
同期 VLA 推論・画像取得・通信の待ち時間もあるため、エピソード全体では低くなります。
RTC による遅延補償は使用していません。

報酬 0 のため、この実機試行でタスク成功や学習による改善は確認できていません。
実機データで Q・編集ポリシーが更新され、結果と replay を保存できることを確認した試行です。

別途、同じモデルの合成 RGB 観測で報酬 0.7 を使った検証では、soft prompt の実際の更新と
モデル・前処理・Learner の保存再読込まで通りました。
その検証での PyTorch 最大割当量は **2.4466 GiB**、最大予約量は **2.4766 GiB**、
行動候補生成は約 **0.114 秒**でした。VLA の学習対象は 983,040 パラメータです。
これらのメモリ値は合成観測での既定 soft prompt 構成に対する値で、実機試行の最大値の実測ではありません。

回帰テストは `tests/test_iloha_xvla_rl.py` と `tests/test_iloha_rl_pipeline.py` の **20 件が成功**しました。
新規コードの Ruff 検査、構文検査、`git diff --check` も成功しました。
